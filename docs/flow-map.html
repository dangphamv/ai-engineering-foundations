Hai thư viện chính: PyTorch và pydantic

Mỗi file dựa vào một thư viện chính. PyTorch dùng để tạo và train model. Pydantic dùng để kiểm tra dữ liệu có đúng hình dạng mong muốn không.

PyTorch
Khái niệm

Thư viện deep learning do Meta phát triển. Nó làm 2 việc chính: tính toán trên tensor (mảng số nhiều chiều) và tự tính đạo hàm cho mọi phép tính.

Cơ chế
  • Tensor: mọi dữ liệu đều là mảng số. 2000 điểm là một tensor shape (2000, 2).
  • Autograd: khi chạy forward, PyTorch ghi lại mọi phép tính thành một đồ thị. backward() đi ngược đồ thị đó để tính gradient.
  • nn.Module: các lớp như Linear giữ tham số (trọng số) bên trong.
  • optim: bộ tối ưu như Adam dùng gradient để sửa tham số.
  • Chạy được trên CPU, GPU NVIDIA (cuda) và chip Apple (mps).
Ví dụ autograd
x = torch.tensor(2.0, requires_grad=True)
y = x**2 + 3*x      # y = 10
y.backward()        # tự tính dy/dx = 2x + 3
x.grad              # tensor(7.)
Công dụng

Train và chạy model: nhận diện ảnh, xử lý ngôn ngữ, LLM. Phần lớn model trên Hugging Face (Llama, Qwen…) được viết bằng PyTorch.

pydantic
Khái niệm

Thư viện kiểm tra và chuyển đổi dữ liệu dựa trên type hint của Python. Bạn mô tả dữ liệu đúng trông thế nào, pydantic chặn mọi thứ không khớp.

Cơ chế
  • Khai báo một class kế thừa BaseModel, mỗi field có kiểu và ràng buộc.
  • Khi nhận dữ liệu (dict hoặc JSON), pydantic kiểm tra từng field. Lõi viết bằng Rust nên chạy rất nhanh.
  • Hợp lệ thì trả về một object có kiểu rõ ràng. Sai thì ném ValidationError, liệt kê đủ từng lỗi.
  • Tự sinh JSON Schema từ class (model_json_schema()).
Ví dụ kiểm tra
class Sentiment(BaseModel):
    label: Literal["positive", "negative", "neutral"]
    confidence: float = Field(ge=0, le=1)

Sentiment.model_validate_json('{"label": "positive", "confidence": 0.9}')
# ✅ Sentiment(label='positive', confidence=0.9)

Sentiment.model_validate_json('{"label": "happy", "confidence": 1.7}')
# ❌ ValidationError: 2 lỗi (label không hợp lệ, confidence > 1)
Công dụng

Kiểm tra request của API (FastAPI dùng pydantic), đọc file cấu hình, và kiểm tra output của LLM trước khi tin dùng.

Flow bên trong từng file

Input: 6 câu review. Output: mỗi câu một nhãn positive / negative / neutral + confidence. Thời gian chờ mạng chiếm gần hết, nên dùng async để 6 request chạy đồng thời trên 1 thread.

Mô phỏng MAX_CONCURRENCY

6 request, mỗi request mất 0.9–1.5 giây chờ mạng

Input: 2000 điểm 2D có nhãn 0/1 (hai hình trăng lồng nhau). Output: một model đoán đúng ~95.5% trên dữ liệu chưa thấy. 50 epoch × 25 batch = 1250 lần cập nhật trọng số.

Loss là gì: kéo thử

Loss = −ln(xác suất model cho đáp án đúng). Không cần nhớ công thức: model càng tự tin vào đáp án đúng thì loss càng gần 0.

Loss khác accuracy: đoán đúng với 51% hay 99% thì accuracy tính như nhau, nhưng loss là 0.67 và 0.01. Model học từ loss vì loss cho biết cần sửa nhiều hay ít.

Vì sao không dùng MoonsMLP thay OpenAI? Lớp đầu là Linear(2, …), chỉ nhận đúng 2 con số. Nó không đọc được chữ. Muốn thay OpenAI thì phải train một model cho văn bản.

Khi nào hai file nối với nhau: dùng sentiment.py gán nhãn vài trăm review (OpenAI làm “thầy”), rồi dùng nhãn đó train một model văn bản nhỏ bằng đúng vòng lặp của train.py (“trò”). Cách này gọi là distillation.
